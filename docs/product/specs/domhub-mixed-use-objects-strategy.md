# DomHub — Mixed-Use Objects Strategy

Статус: short product strategy document  
Назначение: определить, когда DomHub должен включать mixed-use capabilities для объектов с салонами, клиниками, магазинами, кафе и другими компаниями на территории, а когда не должен.

## 1. Core principle

DomHub is first:
- residential operations platform

Only second:
- optional mixed-use governance layer

Это значит:
- mixed-use не должен ломать residential core;
- mixed-use не должен навязываться всем объектам;
- mixed-use включается только там, где есть реальная operational need.

## 2. What is a mixed-use object for DomHub

For DomHub, a property is mixed-use when:
- внутри perimeter есть коммерческие помещения;
- у этих помещений есть staff, visitors, service requests, access and parking needs;
- property team wants those operators inside the same control contour.

Examples:
- салон красоты в стилобате
- клиника в секции
- кофейня/кафе в lobby zone
- магазин на территории
- офис сервисной компании внутри комплекса

## 3. When to enable mixed-use module

Enable the module when all conditions are true:

1. The property has real business operators on site
2. Those operators need repeated operational interaction with the property
3. Access and request flows are easier if managed inside DomHub
4. Property admin wants centralized control

If one of these is missing:
- do not enable by default
- use resident/admin/contractor flows instead

## 4. When not to enable it

Do not enable mixed-use module when:
- there are no commercial premises
- companies appear only occasionally as contractors
- access can be solved with contractor or guest flows
- the property is early-stage pilot and needs a tightly bounded MVP
- commercial accounting is the only perceived reason

In these cases, mixed-use adds complexity without enough value.

## 5. Recommended rollout sequence

### 5.1 Stage 1

Residential core only:
- resident
- security
- concierge
- technician
- contractor
- property admin

### 5.2 Stage 2

Add mixed-use only for qualified pilot properties:
- one or two company types
- bounded company staff flows
- bounded company requests
- bounded company access

### 5.3 Stage 3

Expand mixed-use carefully:
- more company categories
- parking linkage
- stronger governance/reporting

## 6. What mixed-use should cover

Mixed-use module should cover only:
- company registry
- company staff
- scoped access
- scoped requests
- property rules/documents
- optional vehicle/parking linkage

This is enough to solve the real operational problem.

## 7. What mixed-use should not become

Do not let this module turn into:
- lease management system
- commercial billing ERP
- salon CRM
- clinic operating system
- marketplace platform
- booking and reservations suite

If the module grows in those directions, it will distort DomHub product focus.

## 8. Commercial positioning

Use mixed-use strategically as:

> a premium advantage for complex residential properties

Not as:

> the main product identity of DomHub

This strengthens sales for:
- premium ЖК
- business-class mixed-use complexes
- club houses with commercial perimeter services

Without weakening the core message.

## 9. Product decision checklist

Before enabling mixed-use on a property, ask:

- Are there business operators on site?
- Do they need recurring staff access?
- Do they need request workflows?
- Does property admin want centralized governance?
- Can this remain bounded and optional?

If the answer is mostly yes:
- enable the module

If the answer is mixed or no:
- defer it

## 10. Recommended stance for DomHub

The right strategic position is:

- residential-first
- operations-first
- premium-ready
- mixed-use capable where justified

Short version:

> DomHub should support mixed-use properties well, but should never become primarily a commercial property platform.
